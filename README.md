# Лабораторная работа 4 — Композируемость смарт-контрактов

Репозиторий: https://github.com/mysaoka/token-gated-poster-lab4

Работа по Laboratornaya_rabota_4_expanded_and_enhanced.pdf. Новый Poster вызывает balanceOf у токена ERC-20 и разрешает публикацию при balance >= threshold. Проверка не расходует токены.

Используем существующий KWNcoin из ЛР3 в Sepolia:
https://sepolia.etherscan.io/address/0xd3206321bdcbe343eac32bf0fde4a5a93008eabc#code

## Подготовленные этапы

Открыть Open_Project.cmd. В терминале перейти в D:\Lab4_TokenGatedPoster\poster-contract.

1. Начальный token-gating: `node ../scripts/set-stage.mjs 1`. Снимки Poster.sol (адрес токена, порог, конструктор и post), Token.sol из ЛР3 и результата `npx hardhat test` — два теста по методичке.
2. Управление владельцем: `node ../scripts/set-stage.mjs 2`. Снимки owner, onlyOwner, transferOwnership, setTokenAddress и setThreshold. `npx hardhat test` — семь тестов, включая пять дополнительных проверок границ и полномочий.
3. Только после этапа 2: развёртывание `npx hardhat ignition deploy --network sepolia ignition/modules/poster.ts`. Пароль вводится пользователем локально. Владелец по умолчанию — аккаунт развёртывания. Сохранить успешный результат и новый адрес Poster.
4. Верификация: `npx hardhat verify --network sepolia АДРЕС_POSTER 0x0000000000000000000000000000000000000000 0`. Аргументы относятся к конструктору и остаются нулевыми, даже после изменения настроек.
5. После развёртывания владелец вызывает setTokenAddress с адресом KWNcoin выше и setThreshold со значением 10000000000000000000. Это 10 KWN при decimals = 18. Сохранить подтверждения и параметры Read Contract.
6. Интерфейс Poster адаптирован из ЛР2. Запустить Start_UI.cmd и открыть http://localhost:3002 в Chrome с MetaMask. Подключить аккаунт, разрешить переключение в Sepolia. Адрес токена и порог считываются из нового Poster, баланс — из указанного им токена. При недостатке баланса выводится предупреждение до создания транзакции. Проверить публикацию, отказ и отображение сообщений. Баланс повторно проверяется при отправке; чтение постов доступно и без необходимого количества токенов.
7. Опубликовать исходники в отдельном репозитории и дать одногруппнику воспользоваться приложением. Отчёт: ссылка на верифицированный Poster, репозиторий, описание работы, руководство, ответы на пять вопросов методички.

## Уточнения и совместимость

- В тексте «больше порога», но приведённый код отклоняет только balance < threshold. Сохранено поведение кода: равенство разрешено.
- tokenAddress и threshold объявлены public: исходный пример не предоставляет чтение этих полей, необходимое для требования к интерфейсу. Добавлены стандартные getters без изменения правил записи.
- Для установленной версии Hardhat используется network.create() вместо network.connect().
- Для хеширования строкового тега в viem используется keccak256(stringToHex(tag)), чтобы корректно хешировать UTF-8.
- Публичный Poster разворачивается с нулевыми параметрами, как в методичке. До вызова setTokenAddress публиковать нельзя даже при нулевом пороге.
- Тестовые 100n и 10n из методички — минимальные единицы. В Sepolia порог — именно 10 * 10^18. Дополнительный тест проверяет масштабирование.
- RPC-плагин из ЛР3 повторяет только запросы чтения при сетевых обрывах. Журнал Ignition нельзя сбрасывать для повторной попытки после сетевой ошибки.

## Место на диске и секреты

Проект размещён на D:. node_modules подключён junction к D:\Lab3_ERC20\token-contract\node_modules. Не удалять эту папку зависимостей ЛР3 и не устанавливать пакеты через junction. В независимой копии без junction установить зависимости командой npm ci.

Кэш компилятора и npm уже находятся на D: после предыдущих работ. Приватные ключи не копировались: конфигурация использует переменные существующего Hardhat keystore. Скриншоты складывать в документ или Screenshots; секреты не включать.

Интерфейс использует junction poster-ui/node_modules на D:\Lab2_Poster\poster-ui\node_modules. Не удалять зависимости ЛР2 во время работы этой копии. В независимой копии без junction выполнить npm ci в poster-ui, затем npm run dev. Сервисы ЛР2, ЛР3 и ЛР4 используют разные порты: 3000, 3001 и 3002.
